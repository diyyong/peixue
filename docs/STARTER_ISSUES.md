# 首发后可创建的贡献 Issue

这些是 Issue 草案，不代表已经在 GitHub 创建。仓库公开后应逐项改成可验证任务，补上维护者确认的验收标准，再添加标签。

## 1. 增加键盘与屏幕阅读器冒烟检查

建议标签：`good first issue`、`accessibility`、`frontend`

- 用完全虚构数据检查登录、创建记录、时间线、设置和复习流程
- 补齐缺失的可访问名称、焦点样式和合理的标题层级
- 不进行大范围视觉改版
- 提交前运行前端 `npm run check`

## 2. 建立模型供应商兼容性模板

建议标签：`help wanted`、`documentation`、`ai-provider`

- 设计不记录密钥、真实提示内容或儿童数据的验证表
- 覆盖文本分析、视觉识别、复习题、讲解卡、JSON mode 与 SSE
- 只记录维护者可复核的版本、配置和结果，不做笼统兼容声明

## 3. 为 Docker Compose 增加合成数据烟雾测试

建议标签：`help wanted`、`testing`、`docker`

- 从空数据库启动 Compose
- 通过管理 CLI 创建虚构家庭
- 验证健康检查、认证、创建/导出/导入的最短路径
- AI 端点使用本地确定性 stub，不产生外部费用

## 4. 拆分前端 API/SSE 客户端并增加取消测试

建议标签：`help wanted`、`frontend`、`testing`

- 从单文件组件提取普通 JSON 和 SSE 请求逻辑
- 测试网络中断、旧请求回调、错误事件和配额事件
- 保持现有后端协议与用户体验不变

## 5. 改进密码与本地会话说明

建议标签：`good first issue`、`documentation`、`security`

- 在部署与使用说明中清楚区分家庭共享密码、数据库密码和模型密钥
- 增加共享设备清理站点数据的浏览器通用指引
- 不在 UI、文档或测试中展示任何真实凭据
